| `global/security/CurrentUser.java` (신규) | `public record CurrentUser(Long employeeId) { public static CurrentUser from(Jwt jwt) { return new CurrentUser(Long.valueOf(jwt.getSubject())); } }`. Javadoc: JWT subject = 사용자 id(D-06). 신청자 ID는 요청 파라미터가 아니라 반드시 여기서 꺼낸다(NFR-03) |

## T2. Repository 조회

| 파일 | 변경 |
|---|---|
| `enrollment/repository/MyEnrollmentRow.java` (신규) | `public record MyEnrollmentRow(Long enrollmentId, Long sessionId, String courseTitle, LocalDateTime sessionStartsAt, String location, EnrollmentStatus status, Instant appliedAt, Long waitingNo)` |
| `enrollment/repository/EnrollmentRepository.java` | `@Query`(설계 4장 JPQL 그대로, 생성자 식은 패키지 전체 이름) `List<MyEnrollmentRow> findMyEnrollments(@Param("employeeId") Long employeeId, @Param("status") EnrollmentStatus status)`. Javadoc: SQL 1개, 대기 순번 비교식은 `countWaitingAhead`와 같아야 한다(D-36), 바꾸면 둘을 함께 바꾼다 |

- **HQL이 생성자 식 안의 `case` + 서브쿼리를 거부하거나 타입이 맞지 않으면**: 같은 SQL을 `nativeQuery = true` + 인터페이스 프로젝션(또는 `Object[]` 매핑)으로 바꾸고 **보고**한다(설계 4장 위험). SQL 1개 조건은 유지
- 잠금·쓰기 없음

**테스트 (`EnrollmentRepositoryTest`에 추가, 기존 `user`/`session`/`enrollment(...)` 헬퍼 사용)**
- R1 내 것만: A·B가 같은 회차와 다른 회차에 신청 → A 조회 결과의 `enrollmentId`가 A 행만
- R2 정렬: `applied_at` 내림차순, 같은 시각이면 `id` 내림차순
- R3 필터: `WAITING` → 대기만, `null` → 전체
- R4 대기 순번: 한 회차 대기 3명(그중 둘은 같은 `applied_at`) → 각자 순번이 `countWaitingAhead(...) + 1`과 같음, 2번째가 2. CONFIRMED·CANCELLED 행은 `null`
- R5 필드: `courseTitle`·`sessionStartsAt`·`location`이 과정·회차 값과 같음
