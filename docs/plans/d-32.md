## T2. 동시성 테스트 (신규 `backend/src/test/java/com/eduhub/course/CourseAdminConcurrencyTest.java`)

`EnrollmentConcurrencyTest`의 방식을 따른다: `@SpringBootTest`, `@Testcontainers`(disabledWithoutDocker 없음), `@Container @ServiceConnection MySQLContainer("mysql:8.4").withTmpFs(...)`·대기 300초, 클래스에 `@Transactional` 없음, `ExecutorService` + `CountDownLatch`, 작업이 던진 예외는 결과로 모은다. `CourseAdminService`를 직접 호출한다. 과정은 라운드마다 새로 만들고 `@AfterEach`에서 테스트가 만든 과정(그 회차 포함)만 지운다. 회차 시각은 2099년.

| # | 시나리오 (라운드 5 → 검토 후 10, A1은 회차 1개 선생성·회차 수 검증 추가) | 기대 |
|---|---|---|
| A1 | `closeCourse` 1건 + `addSession` 10건 동시 | 예외는 `BusinessException(COURSE_CLOSED)`만 허용(그 밖 0건). 끝나면 과정 CLOSED, 그 과정의 회차가 **모두** CLOSED |
| A2 | `closeCourse` 1건 + `updateCourse` 10건 동시 | 예외는 `COURSE_CLOSED`만. 끝나면 과정 **CLOSED** |
| A3 | `addSession` 10건 동시 | 예외 0건, 회차 번호가 정확히 1~10 |

- implementer는 `compileTestJava`까지만 확인하고 **실행하지 않는다**
- 개발자 확인: `CourseRepository.findByIdForUpdate`의 `@Lock`을 주석 처리하면 A1~A3 중 하나 이상 실패 → 되돌림
