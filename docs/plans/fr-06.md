## T1. 도메인, 오류 코드, Repository, Service

| 파일 | 변경 |
|---|---|
| `global/error/ErrorCode.java` | `CANCEL_NOT_ALLOWED(CONFLICT, "E005", "취소할 수 없는 신청입니다.")`, `CANCEL_PERIOD_ENDED(CONFLICT, "E006", "취소 기간이 지난 회차입니다.")` |
| `enrollment/domain/Enrollment.java` | `public void cancel()`: CONFIRMED·WAITING → CANCELLED, 그 밖 `BusinessException(CANCEL_NOT_ALLOWED)`. `public boolean isConfirmed()`. `public void promote()`: WAITING → CONFIRMED, 그 밖 `IllegalStateException`. `appliedAt`은 바꾸지 않는다 |
| `course/domain/CourseSession.java` | `public void checkCancellable(LocalDateTime now)`: CLOSED 또는 `!now.isBefore(startsAt)` → `BusinessException(CANCEL_PERIOD_ENDED)`. `public void releaseSeat()`: `confirmedCount > 0`이면 −1, 0이면 `IllegalStateException`. Javadoc "회차 잠금 안에서만" |
| `enrollment/repository/EnrollmentRepository.java` | `Optional<Enrollment> findFirstBySessionIdAndStatusOrderByAppliedAtAscIdAsc(Long sessionId, EnrollmentStatus status)` Javadoc: 승급 대상, D-36과 같은 정렬 |
| `enrollment/service/EnrollmentService.java` | `@Transactional public EnrollmentResponse cancel(Long sessionId, Long employeeId)` — 설계 5장 순서 그대로: `findByIdForUpdate`(C002) → `findBySessionIdAndEmployeeId`(E004) → `session.checkCancellable(LocalDateTime.now(clock))` → `wasConfirmed` → `mine.cancel()` → 확정이었으면 `findFirst…(WAITING)`로 `promote()` 또는 `session.releaseSeat()` → `saveAndFlush(mine)` → `EnrollmentResponse.of(mine, null)`. 메서드 Javadoc에 "회차 잠금 앞에 일반 SELECT를 두지 않는다 (D-36)" |

**테스트**
- `EnrollmentTest`: cancel(CONFIRMED·WAITING → CANCELLED, CANCELLED·COMPLETED → E005), promote(WAITING → CONFIRMED, 그 밖 예외), isConfirmed
- `CourseSessionTest`: checkCancellable(시작 1분 전 통과, `now == startsAt` E006, 지남 E006, CLOSED E006), releaseSeat(1 → 0, 0에서 예외)
- `EnrollmentRepositoryTest`: findFirst — 시각 순, 동률 id 순, 재신청 행(작은 id·늦은 시각) 뒤, CONFIRMED·다른 회차 제외, 대기 없으면 empty
- `EnrollmentServiceTest` (Clock.fixed)
  - X1 확정 취소 + 대기 있음 → 내 CANCELLED, 1순위 CONFIRMED, `confirmedCount` 그대로, `releaseSeat` 안 함
  - X2 확정 취소 + 대기 없음 → `confirmedCount` −1
  - X3 대기 취소 → 승급 조회 안 함, 확정 인원 그대로
  - X4 회차 없음 C002 / 신청 없음 E004 / 시작 후 E006 / CLOSED E006 / 이미 취소 E005

**테스트 (`EnrollmentControllerTest`)**
- 신청 후 취소 → 200 `status` CANCELLED, `waitingNo` null, 이어서 `GET me`도 CANCELLED
- 다시 취소 → 409 E005
- 신청 없음 → 404 E004 / 없는 회차 → 404 C002
- 관리자 403 G003, 토큰 없음 401 G002
- 취소 후 재신청 → 201 CONFIRMED (D-02)
- 회귀: 임직원 `POST /api/v1/sessions/{id}/close` → 403 (cancel 매처가 close를 열지 않음)
