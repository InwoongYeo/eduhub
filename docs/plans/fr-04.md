**`EnrollmentService`** — 생성자 주입: `CourseSessionRepository`, `EnrollmentRepository`, `UserRepository`, `Clock`

```java
@Transactional
public EnrollmentResponse enroll(Long sessionId, Long employeeId)
```

설계 5장 순서 그대로:

1. `courseSessionRepository.findByIdForUpdate(sessionId)` → 없으면 `BusinessException(SESSION_NOT_FOUND)`
2. `session.checkEnrollable(LocalDateTime.now(clock))`
3. `userRepository.findById(employeeId)`, 없거나 `!isActive()` → `BusinessException(UNAUTHORIZED)` (설계 Q1)
4. `enrollmentRepository.findBySessionIdAndEmployeeId(sessionId, employeeId)`
   - 있고 `CANCELLED`가 아니면 → `BusinessException(DUPLICATE_ENROLLMENT)` (**reserveSeat 전에** 판정해 자리를 잡지 않는다)
5. `boolean confirmed = session.reserveSeat()`
6. `Instant now = clock.instant()`. 기존 행이 있으면 `existing.reapply(confirmed, now)`, 없으면 `Enrollment.apply(employee, session, confirmed, now)`
7. `enrollmentRepository.saveAndFlush(enrollment)`를 `try`로 감싸 `DataIntegrityViolationException` → `BusinessException(DUPLICATE_ENROLLMENT)`
8. `EnrollmentResponse.from(saved)` 반환

- 잠금 안에서 외부 호출·로그 이외의 작업을 넣지 않는다
- 클래스 Javadoc: FR-04, NFR-01, 잠금 순서(회차 행 하나)

**테스트 (신규)** `backend/src/test/java/com/eduhub/enrollment/service/EnrollmentServiceTest.java` — `@ExtendWith(MockitoExtension.class)` (기존 `CourseServiceTest` 방식), `Clock.fixed(...)` 사용

Javadoc: 범위 잠금(인덱스 순서·간격 잠금), `addSession`과의 교착 가능성(D-32) |
