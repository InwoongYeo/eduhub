## T1. 오류 코드, Repository, DTO, Service

| 파일 | 변경 |
|---|---|
| `global/error/ErrorCode.java` | `ENROLLMENT_NOT_FOUND(NOT_FOUND, "E004", "신청 내역이 없습니다.")` |
| `enrollment/repository/EnrollmentRepository.java` | `@Query` JPQL `long countWaitingAhead(@Param("sessionId") Long sessionId, @Param("appliedAt") Instant appliedAt, @Param("id") Long id)` — 설계 4장 그대로 (`e.status = com.eduhub.enrollment.domain.EnrollmentStatus.WAITING`) |
| `enrollment/dto/EnrollmentResponse.java` | 필드 `Integer waitingNo` 추가 (`@Schema`: 대기 중일 때 1부터, 아니면 null). `status`의 `allowableValues` 제거, 설명은 "CONFIRMED, WAITING, CANCELLED, COMPLETED". `from(Enrollment)`를 `of(Enrollment enrollment, Integer waitingNo)`로 교체. 클래스 Javadoc의 "FR-05에서 추가" 문구 정리 |
| `enrollment/service/EnrollmentService.java` | `enroll`: `saveAndFlush` 결과가 `WAITING`이면 `waitingNoOf(saved)`, 아니면 null로 `EnrollmentResponse.of`. 기존 `try/catch`(유일 제약 → E001)는 유지하되 순번 계산은 catch 밖에서<br>신규 `public EnrollmentResponse findMine(Long sessionId, Long employeeId)` (클래스 기본 readOnly): `courseSessionRepository.existsById` 아니면 C002, `findBySessionIdAndEmployeeId` 없으면 E004, 있으면 `of(e, WAITING이면 순번 아니면 null)`<br>private `Integer waitingNoOf(Enrollment e)` = `(int) countWaitingAhead(sessionId, e.getAppliedAt(), e.getId()) + 1` |

**테스트**
- `EnrollmentServiceTest`(Mockito): 기존 U1~U10 유지(응답 생성 방식만 맞춤). 추가
  - U11 정원 참 → `countWaitingAhead`가 3이면 `waitingNo` 4
  - U12 자리 있음 → `waitingNo` null, `countWaitingAhead` 호출 안 함
  - U13 `findMine` 대기 → 순번 / 확정 → null / 신청 없음 → E004 / 회차 없음 → C002
- `EnrollmentRepositoryTest`(H2): `countWaitingAhead` — 대기 3명 시각 다르게 → 0, 1, 2. 같은 시각 2명 → id 작은 쪽 0, 큰 쪽 1. CONFIRMED·CANCELLED는 세지 않음. 다른 회차는 세지 않음
