# EduHub 요구사항

## 개요

EduHub는 **온라인 강의 수강 관리 서비스**다. 강사가 강의를 개설하고, 학생이 수강 신청하며, 관리자가 사용자와 강의를 관리한다.

**사용자**

- **학생**: 강의를 찾아 수강 신청한다.
- **강사**: 강의를 개설하고 운영한다.
- **관리자**: 사용자와 강의를 관리한다.

## 기술 스택

| 구분 | 기술 |
|---|---|
| 백엔드 | Java 21, Spring Boot 4.1.2 (D-09) |
| 보안 | Spring Security + JWT |
| 데이터 | Spring Data JPA, H2(개발) / MySQL(운영) |
| API 문서 | springdoc-openapi (Swagger UI) |
| 빌드·테스트 | Gradle, JUnit 5 |

## 기능 요구사항 (FR)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | 이메일·비밀번호로 회원가입, 로그인할 수 있다 | 높음 |
| FR-02 | 강사는 강의를 등록·수정·삭제할 수 있다 | 높음 |
| FR-03 | 누구나 강의 목록을 조회·검색할 수 있다 | 높음 |
| FR-04 | 학생은 강의를 수강 신청·취소할 수 있다 | 높음 |
| FR-05 | 학생은 내 수강 목록을 볼 수 있다 | 중간 |
| FR-06 | 강사는 자기 강의의 수강생 목록을 볼 수 있다 | 중간 |
| FR-07 | 강의에는 정원이 있고, 정원이 차면 신청할 수 없다 | 중간 |
| FR-08 | 관리자는 사용자 계정을 비활성화할 수 있다 | 낮음 |

## 비기능 요구사항 (NFR)

| ID | 요구사항 | 기준 |
|---|---|---|
| NFR-01 | 보안 | 비밀번호는 BCrypt로 암호화, 역할(학생·강사·관리자)별 접근 제어 |
| NFR-02 | API 문서 | 모든 API가 Swagger UI에 노출된다 |
| NFR-03 | 품질 | 서비스 계층 단위 테스트 작성, 오류 응답 형식 통일 |
| NFR-04 | 환경 분리 | `local` / `prod` 프로필 분리, 비밀 값은 환경 변수로 주입 |
| NFR-05 | 성능 | 강의 목록 조회는 페이지 단위, 응답 500ms 이내 |
| NFR-06 | 유지보수 | 기능(도메인)별 패키지 구조 |

## 결정 사항

| ID | 질문 | 결정 | 관련 |
|---|---|---|---|
| D-01 | 한 계정이 강사이면서 학생일 수 있는가 | 계정당 역할은 하나 | NFR-01 |
| D-02 | 수강 취소 기한과 재신청 | 강의 시작 전까지 취소 가능, 취소 후 재신청 가능 | FR-04 |
| D-03 | 수강생이 있는 강의 삭제 | 수강생이 있으면 삭제 불가, "폐강" 상태로 전환 | FR-02 |
| D-04 | 최초 관리자 계정 생성 | `local`은 초기 데이터, `prod`는 환경 변수로 생성 | FR-08, NFR-04 |
| D-05 | 강의 검색 범위 | 제목과 강사 이름 | FR-03 |
| D-06 | JWT 발급·검증 시점 | 2주차로 미룬다. 1주차는 보안 설정·BCrypt·URL 권한 틀만 | NFR-01 |
| D-07 | prod에서 Swagger UI | 끈다 (`local`에서만 노출) | NFR-02, NFR-04 |
| D-08 | 1주차 NFR 반영 범위 | 보안 뼈대, API 문서, 품질(오류 형식·테스트 환경), 프로필, 패키지 구조. 성능은 페이지 단위 설계만 | NFR-01~06 |
| D-09 | Spring Boot 버전 | 4.1.2 (3.x는 무료 지원 종료, Initializr도 4.x만 제공) | 기술 스택 |
